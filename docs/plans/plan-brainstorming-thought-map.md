# Implementation Plan — brainstorming thought map

*২০২৬-০৯-১৩*

## আমরা কী তৈরি করছি

`brainstorming/`-এ একটা `AGENTS.md` (আর `CLAUDE.md`, ভেতরে শুধু `@AGENTS.md`)। এর নির্দেশ অনুযায়ী যেকোনো agent সেশন শুরু হলে ফোল্ডারের `.md` ফাইলগুলো `thought-map.md`-এর ফাইল-তালিকার সাথে মেলাবে। নতুন ফাইল পেলে সেগুলো পড়বে, আর `thought-map.md` আপডেট করবে। ফাইলটায় থাকবে একটা Mermaid `mindmap` (মাঝে মূল লক্ষ্য, চারদিকে স্তর, স্তরের ভেতরে ফাইল ও ধারণা), একটা "যোগসূত্র" টেবিল, আর একটা "অমিল" সেকশন। প্রথমবার বর্তমান ৩৯টা ফাইল দিয়ে map তৈরি হবে।

## যে পরিভাষাগুলোতে আমরা সম্মত হয়েছি

* **নতুন ফাইল:** এমন `.md` ফাইল যেটা `thought-map.md`-এর ফাইল-তালিকায় নেই, git-এ commit হোক বা না হোক। পুরনো ফাইলে লেখা বদলানো "নতুন" নয়।
* **খুঁজে বের করা:** agent সেশন শুরু হলে (বা ব্যবহারকারী বললে) যাচাই। পেছনে সারাক্ষণ নজর রাখা নয়।
* **নতুন md ফাইল:** একটাই জীবন্ত ফাইল, `thought-map.md`, প্রতিবার আপডেট হয়। আলাদা snapshot নয়।
* **visualize:** Mermaid diagram, GitHub ও VS Code-এ ছবি হয়ে দেখায়।
* **connected:** দুই ধরনের — স্পষ্ট (এক ফাইলে অন্য ফাইলের link) আর ধারণাগত (একই ধারণা একাধিক ফাইলে)।

## নেওয়া সিদ্ধান্তসমূহ

* **ধরার ব্যবস্থা — শুধু AGENTS.md-এর নির্দেশ (hook নয়):** repo-টা শুধু markdown; ফাইল মেলানো agent-এর এক ধাপের কাজ; আর নতুন script মানে আরেকটা টুল, যেটা এই repo-র নিজের সতর্কতার বিপরীত। agent বারবার ভুলে গেলে পরে SessionStart hook যোগ হবে।
* **diagram — Mermaid `mindmap`:** ব্যবহারকারীর দেওয়া ছবির মতো, কেন্দ্র থেকে শাখা। mindmap আড়াআড়ি তীর আঁকতে পারে না, তাই ধারণাগত সংযোগ যাবে diagram-এর নিচের "যোগসূত্র" টেবিলে।
* **অমিল সেকশন:** নতুন ফাইল পুরনো ফাইলের সাথে বিরোধ করলে agent সেটা "অমিল"-এ লিখবে এবং ব্যবহারকারীকে জিজ্ঞেস করবে — নিজে কোনো ফাইল ঠিক করবে না।
* **প্ল্যানের জায়গা:** `brainstorming/docs/plans/`।

## অনুমানসমূহ (Assumptions)

* map-এর কেন্দ্র (root): "২০২৮-০৯: মাসে ২ লাখের চাকরি" — ব্যবহারকারীর বর্তমান লক্ষ্য। লক্ষ্য বদলালে root বদলাবে।
* স্ক্যান থেকে বাদ: `thought-map.md`, `AGENTS.md`, `CLAUDE.md`, `README.md`, আর `docs/plans/`।
* mindmap-এ ফাইলের নাম ছোট লেবেলে দেখানো হবে (যেমন `after-getting-response/03` → "HR call"); পুরো path থাকবে ফাইল-তালিকা ও যোগসূত্র টেবিলে।
* শাখা বেশি হলে পড়া যায় না, তাই প্রতি স্তরে সর্বোচ্চ ~৬টা পাতা; বেশি হলে উপ-শাখায় ভাগ।
* root `README.md`-এর টেবিলে `brainstorming` যোগ হবে (repo: `sojibrd/brainstorming`, live URL নেই)।

## যেভাবে এটি তৈরি করতে হবে

1. `brainstorming/AGENTS.md` লেখা — উদ্দেশ্য, স্ক্যানের নিয়ম (কোন ফাইল গোনা হবে, কোনটা বাদ), নতুন ফাইল পেলে কী করতে হবে, `thought-map.md`-এর গঠন, অমিল ধরলে জিজ্ঞেস করার নিয়ম। বাংলায়, workspace-এর বাকি AGENTS.md-এর মতো।
2. `brainstorming/CLAUDE.md` — শুধু `@AGENTS.md`।
3. `brainstorming/thought-map.md` প্রথমবার তৈরি — ৩৯টা ফাইল দিয়ে:
   - ফাইল-তালিকা (স্ক্যানের রেকর্ড)
   - Mermaid `mindmap` — ৮টা স্তর: মূল রোগ → প্রথম লক্ষ্য → কোন বাজার → প্রমাণ → আবেদন থেকে offer → সহায়ক প্রস্তুতি → যোগ দেওয়ার পরে → দূরের অঙ্ক
   - যোগসূত্র টেবিল — টুল বানানোর ফাঁদ, মুখে ইংরেজি, STAR story, "[Your Name]", সঞ্চয় ও সোনা, `leave_management`, Stage 1
   - অমিল সেকশন — এখন পর্যন্ত মীমাংসিত অমিলগুলোর ছোট রেকর্ড, খোলা অমিল থাকলে সেগুলো
4. Mermaid syntax যাচাই (বাংলা লেবেল আর বন্ধনীতে mindmap ভাঙে কিনা)।
5. root `README.md`-এর প্রজেক্ট টেবিলে `brainstorming` সারি; root `AGENTS.md`-এর Projects তালিকায় একটা ছোট অংশ।
6. যাচাই: একটা পরীক্ষামূলক ফাইল যোগ করে নির্দেশ অনুযায়ী ধরা পড়ে কিনা দেখা, তারপর সেটা মুছে ফেলা।
