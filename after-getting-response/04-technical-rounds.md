# ধাপ ৪ — কারিগরি রাউন্ড

*উত্তরের চেয়ে বেশি দেখা হয় আপনি কীভাবে ভাবছেন · ২০২৬-০৯*

## চার ধরনের রাউন্ড

কোম্পানিভেদে এক বা একাধিক রাউন্ড হতে পারে: **take-home task, live coding, framework নিয়ে গভীর আলোচনা, আর frontend system design।** প্রথম কলেই জিজ্ঞেস করে নিন কোনগুলো হবে, তারপর শুধু সেগুলোর জন্য প্রস্তুতি নিন।

## Take-home task

এখানে আপনার চেনা ফাঁদ হলো দরকারের চেয়ে বেশি বানিয়ে ফেলা। ওরা "৪ ঘণ্টা" বললে সময় ধরে ৪ ঘণ্টাই কাজ করবেন। কোনো চাহিদা অস্পষ্ট লাগলে কাজ শুরুর আগে ইমেইলে জিজ্ঞেস করে নিন। এটা ভালো লক্ষণ হিসেবেই দেখা হয়। যা জমা দেবেন:

- **README:** কীভাবে চালাতে হয়, কোন সিদ্ধান্ত কেন নিয়েছেন, আর সময় থাকলে আর কী করতেন। এই শেষ অংশটায় বাড়তি ফিচার বানাতে হয় না, শুধু লিখে দিলেই চলে।
- **মূল logic-এর জন্য কয়েকটা test,** সবকিছুর জন্য নয়।
- **পরিষ্কার commit history,** "final", "final2", "fix" নয়।
- একটা live link দিতে পারলে ভালো। Next.js-এ deploy করা আপনার জন্য পাঁচ মিনিটের কাজ।

## Live coding

**কোড লেখার আগে সবসময় একই ক্রমে শুরু করুন।** আপনি নিজেই লিখেছিলেন যে clarifying question করতে পারেন না। ক্রমটা মুখস্থ থাকলে ওই সমস্যা অনেকটা মিটে যায়:

1. সমস্যাটা নিজের ভাষায় আবার বলুন: *"So I need to... is that right?"*
2. input নিয়ে দুটো প্রশ্ন করুন: *"Can the array be empty? Are there duplicates?"*
3. একটা ছোট উদাহরণ হাতে কষে দেখান।
4. সহজ সমাধানটা আগে বলুন, তারপর কীভাবে ভালো করা যায়: *"A simple approach is O(n²); I think a hash map gets it to O(n)."*
5. কোড লিখুন, আর লেখার সময় মুখে বলতে থাকুন কী করছেন।
6. উদাহরণ দিয়ে কোডটা পরীক্ষা করুন, তারপর time আর space complexity বলুন।

Frontend পদে প্রায়ই সরাসরি একটা component বানাতে বলা হয়।
 এই পাঁচটা অনুশীলন করে রাখুন: **debounced search, modal (focus trap সহ), infinite scroll, tabs (keyboard navigation সহ), আর পাতা ভাগ করা table।**

## Framework নিয়ে গভীর আলোচনা

এখানে জিজ্ঞেস করা হয় জিনিসগুলো "কেন" এভাবে কাজ করে, শুধু "কীভাবে" ব্যবহার করতে হয় তা নয়। চারটা বিষয় নিজের কথায় ব্যাখ্যা করার অনুশীলন করুন: **Ember-এর autotracking আর React-এর re-render কীভাবে আলাদা; কোন state কোথায় রাখবেন (component, service, নাকি URL); async কাজে ember-concurrency-র task বনাম React-এর useEffect; আর browser-এর event loop, rendering pipeline ও Core Web Vitals।**

**Ember আপনার শক্তির জায়গা।** প্রশ্নটা React নিয়ে হলেও উত্তরে Ember-এর সাথে তুলনা করতে পারেন: *"In Ember we'd solve this with a restartable task; in React I'd use an AbortController."* এতে বোঝা যায় আপনি একটা framework-এর নিয়ম মুখস্থ করেননি, মূল ধারণাটা বোঝেন।

## Frontend system design

সাধারণত প্রশ্ন আসে এমন: *"একটা autocomplete বা news feed-এর UI ডিজাইন করুন।"* উত্তর এই ক্রমে সাজান: কী কী চাহিদা আছে → component-গুলো কী হবে → state কোথায় থাকবে → ডেটা কীভাবে আনবেন ও cache করবেন → performance → accessibility। আঁকার চেয়ে বেশি জরুরি প্রতিটা সিদ্ধান্তের কারণ বলা।

## আটকে গেলে

চুপ করে থাকবেন না। বলুন আপনি কোথায় আটকেছেন, মাথায় কী কী পথ ঘুরছে, আর দরকার হলে সরাসরি একটা hint চান: *"I'm stuck between two approaches — could I get a hint?"* hint চাইলে নম্বর কাটে না। চুপচাপ দশ মিনিট বসে থাকলে কাটে।

## মানসিক কাঠামো

- **ওরা আপনার সাথে কাজ করলে কেমন লাগবে সেটা দেখছে।** সঠিক উত্তর কিন্তু একটা শব্দও না বলা প্রার্থীর চেয়ে ভুল পথে গিয়েও মুখে ভেবে চলা প্রার্থী বেশি নম্বর পায়। কারণ কাজের সময় ওদের দরকার এমন সহকর্মী, যার চিন্তা বোঝা যায়।
- **ভাঙা ইংরেজিতে জোরে ভাবা চুপ থাকার চেয়ে ভালো।** ব্যাকরণ কেউ মাপে না, মাপে আপনার চিন্তা কতটা স্পষ্ট।
